## 4. 度量纪律 (本循环反复栽过的地方, 比结论更值得带走)

1. **注入之后先确认它落地了** —— "不响"有四种: 注入无效 / 判据太弱 / **注入目标与被测性质不同** /
   **注入自指**(探针读 `__file__` ⇒ 答案写进被测对象)。见 §13.122。
2. **判据的单位与作用域弱于它声称的性质** —— 这是本册出现最多的一类守卫缺陷;
   每次都要问: 「**改掉被检查的东西, 这条断言会怎样?**」以及「**这条判据的扫描范围覆盖到缺陷住的地方了吗?**」。
3. **同名 ≠ 同义** —— 四族的 `cagr`/`sharpe`/`max_dd`/`win_rate` **定义都不同** (§13.13);
   跨族**不得**按这些量排序 (§13.90 的守卫)。
4. **任何收益差, 先问它由几笔撑着** —— §13.130: 报告窗的头条由 **3 笔**撑;
   §13.132: 去掉 3 笔则 15 个滚动窗**无一赢市场**。
5. **一个数字引用时必须带的三样**: ①同构造基准 ②去掉最好 3 笔后的值 ③滚动窗分布 (§13.127/130/132)。
6. **归因不许靠推理** —— 判"是不是我引起的", 用 A/B 实测 (换回改前的文件、删缓存、两边重跑)。
7. **"声明" ≠ "做到"** —— preset 里声明着的键不一定被引擎读 (§13.128 的逐键变异;
   实例: `price_source_for_signal` 被 **82/82** 个 preset 声明而零引擎消费)。
8. **先看"产生结果的过程", 再看"结果的形状"** (§12.6)。
9. **中文文本里的强调一律用 「」** —— 在 Python / shell 字符串里嵌 ASCII 双引号会**静默截断**,
   本会话已因此多次让"写了但没落盘"。**写完多语句的脚本后必须回读核验产物。**
